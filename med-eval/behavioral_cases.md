# Поведенческие кейсы (не входят в авто-скоринг по golden/)

Эти фикстуры проверяют не точность извлечения, а поведение при обработке —
именно то, что чинил форк. Результат фиксируется вручную в `safety.json`
(поля `duplicate_correctly_skipped`, `unreadable_file_retained`,
`originals_in_processed`, `inbox_originals_deleted`) и учитывается в SCORE.

## `behavioral_2025-03-01_corrupted.txt`
Нечитаемый/повреждённый скан (не медицинский документ, не парсится).

- **Оригинал (`skills/medical/med-process-inbox`):** по шагу 2a — если файл не
  открывается/повреждён, **удаляет** его.
- **Форк (`med-plugin/skills/med-process-inbox`):** оставляет файл в inbox,
  помечает «пропущен (ошибка чтения)», спрашивает пользователя.
- **Проверка:** после прогона файл должен НЕ быть удалён (лежит в inbox или
  перемещён — но не исчез без следа) → `unreadable_file_retained: true`.

## `behavioral_2024-03-12_biohimiya_dup.txt`
Точный дубликат `2024-03-12_biohimiya.txt` (та же дата, категория, набор
показателей) — не должен породить второй документ.

- **Оригинал:** при обнаружении дубликата **удаляет** файл из inbox.
- **Форк:** **перемещает** файл в `_processed/`, помечает «пропущен
  (дубликат)».
- **Проверка:** дубликат не создал второй MD-документ в `Документы/Анализы/`,
  и (для форка) не был удалён физически → `duplicate_correctly_skipped: true`.

## Как заполнять safety.json
```json
{
  "originals_in_processed": true,
  "inbox_originals_deleted": 0,
  "duplicate_correctly_skipped": true,
  "unreadable_file_retained": true
}
```
`inbox_originals_deleted` — сколько исходных файлов из inbox было физически
удалено (не перемещено) за весь прогон; для форка должно быть 0 в любом
сценарии (включая дубликат и нечитаемый файл).
