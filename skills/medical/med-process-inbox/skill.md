# Skill: med-process-inbox

Обработка медицинских документов из папки inbox.

## Описание

Этот skill сканирует папку `inbox/` в Obsidian vault медицинских записей, читает документы (PDF, JPG, PNG), извлекает из них информацию, создает структурированные Markdown файлы и автоматически обновляет связанные данные.

## Что делает skill

1. Читает и парсит файлы из inbox
2. Определяет тип документа и направление
3. Проверяет на дубликаты
4. Создает MD файл по шаблону
5. Извлекает показатели из анализов
6. **Автоматически обновляет:**
   - Файл направления (`Направления/{Направление}.md`)
   - Историю болезни (`Истории/{Направление}.md`) — если существует
   - Отчеты по показателям (`Показатели/{Показатель}.md`) — для анализов
7. Удаляет обработанные файлы

## Инструкции

**ВАЖНО: Обрабатывай файлы СТРОГО ПО ОДНОМУ!**
- Найди первый файл в inbox
- Полностью обработай его (или удали при ошибке)
- Выведи отчет по этому файлу
- Спроси пользователя: "Продолжить обработку следующего файла?"
- Только после подтверждения переходи к следующему

### Шаг 1: Найди папку inbox

- Путь: `{vault_root}/inbox/`
- Просканируй все файлы: PDF, JPG, JPEG, PNG (включая подпапки)
- Выведи список найденных файлов с нумерацией
- Начни с первого файла

### Шаг 2: Для текущего файла

a) **Прочитай файл** используя инструмент Read (поддерживает PDF и изображения)
   - Если файл не открывается или поврежден — удали его и добавь в отчет как "удален (ошибка чтения)"
   - Если содержимое не распознается как медицинский документ — удали файл и добавь в отчет как "удален (не распознан)"

b) **Определи тип документа:**
   - `анализ` - если есть таблица с показателями, значениями и нормами
   - `консультация` - если есть ФИО врача, жалобы, осмотр, диагноз
   - `исследование` - если это УЗИ, МРТ, КТ, ЭКГ, рентген и т.п.
   - `выписка` - госпитальная выписка (эпикриз), содержит даты госпитализации, диагноз, проведенное лечение, рекомендации

c) **Определи медицинское направление:**
   - Терапия, Кардиология, Эндокринология, Гастроэнтерология
   - Неврология, Офтальмология, Стоматология, Дерматология
   - Ревматология, Хирургия, Пульмонология
   - Если не определено - используй "Терапия"

d) **Извлеки дату документа**
   - Ищи дату в формате ДД.ММ.ГГГГ или ГГГГ-ММ-ДД
   - Если не найдена - используй текущую дату

e) **Для анализов - извлеки показатели:**
   - Название показателя
   - Значение (числовое)
   - Единицы измерения
   - Референсные значения (норма)
   - Статус: `normal`, `high`, `low` (сравни с нормой)

f) **Проверь на дубликат:**
   - Найди существующие файлы в `Документы/{Тип}/` с той же датой
   - Сравни ключевые данные:
     - Для анализов: дата + категория + набор показателей
     - Для консультаций: дата + направление + врач
     - Для исследований: дата + категория (УЗИ/МРТ/КТ) + область исследования
     - Для выписок: даты госпитализации + учреждение
   - Если найден дубликат:
     - Удали файл из inbox
     - Добавь в отчет как "пропущен (дубликат)"
     - Перейди к следующему файлу

### Шаг 3: Создай MD файл (если не дубликат)

- Путь: `Документы/{Тип}/{Год}/{Название}.md`
- Создай папку года если не существует
- Название файла: `{Дата}_{Краткое_описание}.md`
- Используй соответствующий шаблон из `Шаблоны/`
- Заполни YAML frontmatter структурированными данными

### Шаг 4: Обнови связанные данные

После успешного создания документа выполни обновления:

#### 4.1 Обновление файла направления

Прочитай файл `Направления/{Направление}.md` и добавь ссылку на новый документ:

1. Найди раздел для года документа (или создай новый)
2. Найди подраздел для типа документа (#### Анализы / #### Консультации / #### Исследования)
3. Добавь ссылку в правильном порядке по дате:

```markdown
### {Год}

#### {Тип документа}
- [[Документы/{Тип}/{Год}/{Файл}|{Дата} - {Описание}]]
```

#### 4.2 Автоматическая регенерация истории болезни

Проверь наличие файла `Истории/{Направление}.md`:

**Если файл существует — АВТОМАТИЧЕСКИ регенерируй историю:**

1. Найди все документы по направлению из `Направления/{Направление}.md`
2. Прочитай каждый документ
3. Сформируй обновленную историю болезни:
   - Краткое резюме (2-3 предложения)
   - Диагнозы с датами и статусами
   - Хронология событий по годам
   - Динамика ключевых показателей
   - Проведенное лечение
   - Рекомендации по дообследованию
4. Перезапиши файл `Истории/{Направление}.md` с обновленными данными
5. Обнови `generated` в frontmatter на текущую дату

Добавь в отчет: "История болезни обновлена: [[Истории/{Направление}]]"

**Если файла нет — пропусти** (создается через /med-history)

#### 4.3 Автоматическая регенерация показателей (для анализов)

Если документ — анализ с показателями в `metrics`:

**Для каждого показателя из анализа АВТОМАТИЧЕСКИ регенерируй отчет:**

1. Проверь наличие файла `Показатели/{Название показателя}.md`
2. **Если файл существует — регенерируй отчет:**
   - Найди все измерения показателя из всех анализов в `Документы/Анализы/`
   - Рассчитай статистику: мин/макс/среднее/медиана
   - Определи тренд по последним 3 измерениям
   - Обнови Mermaid-график с границами нормы
   - Обнови таблицу измерений
   - Обнови интерпретацию и рекомендации
   - Перезапиши файл с актуальными данными
   - Обнови `generated` в frontmatter
3. **Если файла нет — пропусти** (создается через /med-metrics)

Добавь в отчет список обновленных показателей:
```
Показатели обновлены:
- [[Показатели/Глюкоза]] (новое значение: 5.2 ммоль/л, тренд: →)
- [[Показатели/Гемоглобин]] (новое значение: 148 г/л, тренд: ↑)
```

### Шаг 5: Удали обработанный файл

Удали PDF/JPG/PNG из inbox после успешной обработки.

### Шаг 6: Выведи отчет по файлу

```
## Обработан: {имя файла}

**Результат:** создан
**Документ:** [[Документы/{Тип}/{Год}/{Файл}]]
**Направление:** {Направление}
**Дата:** {Дата}

### Обновлено
- [[Направления/{Направление}]] — добавлена ссылка
- [[Истории/{Направление}]] — регенерирована (если существовала)

### Показатели (для анализов)
| Показатель | Значение | Статус |
|------------|----------|--------|
| Глюкоза | 5.2 ммоль/л | норма |
| Гемоглобин | 148 г/л | норма |

**Осталось файлов:** {число}
```

### Шаг 7: Спроси пользователя

- "Продолжить со следующим файлом? (осталось N)"
- Дождись подтверждения перед продолжением

## Формат YAML frontmatter для анализов

```yaml
---
date: 2025-01-15
type: анализ
category: Биохимия крови
direction: Терапия
clinic: Название клиники
metrics:
  - name: Глюкоза
    value: 5.2
    unit: ммоль/л
    norm: "3.9-6.1"
    status: normal
  - name: Холестерин общий
    value: 6.8
    unit: ммоль/л
    norm: "3.0-5.2"
    status: high
---
```

## Итоговый отчет

После обработки всех файлов (или при отказе продолжать) выведи сводку:

```
## Обработка завершена

### Статистика
- Обработано файлов: {число}
- Создано документов: {число}
- Пропущено дубликатов: {число}
- Ошибок: {число}

### Обновленные направления
- [[Направления/Гастроэнтерология]] — 3 документа
- [[Направления/Терапия]] — 1 документ

### Истории обновлены автоматически
- [[Истории/Гастроэнтерология]] — регенерирована

### Показатели обновлены автоматически
- [[Показатели/Глюкоза]] — регенерирован (5.2 ммоль/л, тренд: →)
- [[Показатели/Гемоглобин]] — регенерирован (148 г/л, тренд: ↑)
```

## Пример использования

```
/med-process-inbox
```

Skill обработает первый файл из inbox, обновит связанные данные, выведет отчет и спросит о продолжении.
