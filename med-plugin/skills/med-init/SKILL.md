# med-init

Инициализация структуры медицинского Obsidian-vault.

## Использование
```
/med-init
```

## Инструкции

### Шаг 1. Подтверждение директории
1. Выполни `pwd`.
2. Покажи пользователю путь и структуру, которая будет создана, и спроси
   подтверждение (y/n). Структура:
   - `inbox/` — необработанные документы (PDF, JPG, PNG)
   - `_processed/` — оригиналы после обработки (НЕ удаляются)
   - `Документы/` → `Анализы/`, `Консультации/`, `Исследования/`, `Выписки/`
   - `Направления/` — индексы по направлениям
   - `Истории/` — аналитические отчёты
   - `Показатели/` — динамика показателей
3. При отказе — заверши, подскажи как сменить директорию.

### Шаг 2. Папки
Создай только недостающее, existing не трогай:
```bash
mkdir -p inbox _processed \
  Документы/Анализы Документы/Консультации Документы/Исследования Документы/Выписки \
  Направления Истории Показатели
touch inbox/.gitkeep
```
`.gitkeep` нужен, чтобы пустая `inbox/` не терялась в git несмотря на
исключение `_processed/` в `.gitignore` (см. Шаг 5).

### Шаг 3. Файлы направлений
Создай в `Направления/` по одному файлу на направление (Терапия,
Гастроэнтерология, Неврология, Кардиология, Эндокринология, Офтальмология,
Стоматология, Дерматология, Ревматология, Пульмонология) с единой структурой:
```markdown
# {Направление}
## Хронология
### 2025
#### Консультации
#### Анализы
#### Исследования
#### Выписки
```
Не перезаписывай уже существующие файлы.

### Шаг 4. Регистр показателей
Создай `Показатели/_registry.md` с заголовком, пометкой «заполняется и
обновляется через /med-process-inbox, /med-metrics и /med-index» и краткой
шпаргалкой по командам.

### Шаг 5. README и .gitignore
Создай `README.md` в корне (структура + быстрый старт) и `.gitignore`:
```
inbox/*
!inbox/.gitkeep
_processed/
.obsidian/
.trash/
.DS_Store
*.backup
```
`inbox` и `_processed` исключаются из git — там оригиналы с персональными данными.

### Шаг 6. Отчёт и напоминание о безопасности
Выведи, что создано, и обязательно напомни:
- vault содержит медицинские данные — храни на зашифрованном диске;
- не синхронизируй с публичными облаками без шифрования;
- оригиналы документов остаются в `_processed/`, делай их резервную копию.
