# med-metrics

Визуализация динамики медицинских показателей с проверкой референсов по базе знаний.

## Использование

```
/med-metrics                      # список всех показателей
/med-metrics Глюкоза              # график динамики
/med-metrics Глюкоза,Гемоглобин   # сравнение
/med-metrics --abnormal           # только вне нормы
```

## Инструкции

### Шаг 1. Сбор данных
1. Найди все MD-файлы в `Документы/Анализы/`.
2. Извлеки из YAML frontmatter каждого: `date` и массив `metrics` (name, value, unit, norm, status).

### Шаг 2. Расчёт статистики — ТОЛЬКО через исполнение кода
**Не считай min/max/среднее/медиану/тренд в уме.** Собери значения показателя
в список и вычисли их исполнением Python (tool code execution). Ручной подсчёт
на медицинских числах недопустим — ошибка в отнесении значения к «норме/высокому»
имеет цену. Верни из кода: min, max, mean, median, а также тренд по последним
3 измерениям.

**Правило тренда** (детерминированное, не оценка модели): сравни последнее
значение со средним двух предыдущих из последних трёх измерений. Если
предыдущих измерений всего одно (ровно 2 измерения в наборе) — сравнивай
последнее значение напрямую с этим единственным предыдущим (тот же порог).
- **up** — последнее выше этого среднего (или единственного предыдущего) более чем на 10%
- **down** — последнее ниже этого среднего (или единственного предыдущего) более чем на 10%
- **stable** — отклонение в пределах ±10%
- **unknown** — меньше 2 измерений

Это правило одинаковое для любого показателя — не подбирай другой порог по
ситуации, иначе тренд станет невоспроизводимым между запусками.

### Шаг 3. Проверка референсных границ по базе знаний
Перед тем как пометить значение как «норма/высокий/низкий», сверь референсный
интервал через MCP-инструмент базы знаний:

- вызови MCP-инструмент `medrag` (chroma query) с коллекцией `medrag_textbooks`
  (см. `rag/build_index.py`) и запросом вида
  `"reference range <показатель> <пол/возраст если есть> normal values"`;
- если норма из документа расходится с найденной в базе — НЕ переписывай молча:
  покажи обе и пометь расхождение как «требует уточнения (лаборатория vs источник)».
- база знаний англоязычная (MedRAG); формулируй запрос по-английски,
  результат интерпретируй для пользователя по-русски.
- **перед сравнением всегда проверь единицы измерения.** Англоязычные
  источники нередко дают референс в других единицах, чем русская
  лаборатория (например, глюкоза в mg/dL против ммоль/л) — сравнение
  значений в разных единицах без конвертации даст неверный статус
  (норма/высокий/низкий). Если единицы отличаются — сконвертируй одно в
  другое (код, не в уме) и явно укажи коэффициент в отчёте.
- если `medrag` недоступен или запрос не вернул результата — не подставляй
  норму по памяти молча: используй норму из документа, если она есть, а если
  нет — оставь `norm` пустым и используй статус `unknown`; в тексте отчёта
  явно укажи «норма не подтверждена (база знаний недоступна)».

База знаний используется ТОЛЬКО для проверки фактов (референсы, единицы,
клиническое значение показателя). Она не используется для выводов о причинах
отклонений у конкретного пациента.

### Шаг 4. График и сохранение
- ASCII-график для чата + Mermaid `xychart-beta` с горизонтальными линиями границ нормы.
- Сохрани отчёт в `Показатели/{Показатель}.md` с frontmatter
  (metric, unit, norm, generated, measurements, period_start, period_end,
  last_value, last_status, trend) и таблицей всех измерений со ссылками на источники.
- Обнови `Показатели/_registry.md`.

### Шаг 5. Дисклеймер в отчёте
В конце файла: значения и тренды получены из твоих анализов; референсы сверены
с общей медицинской базой знаний; интерпретация отклонений — вопрос к врачу,
не диагноз.

## Другие режимы вызова

### Без аргументов — список всех показателей
Не выполняй Шаги 2-5 для конкретного показателя. Вместо этого: для каждого
уникального показателя (имя+единицы) собери число измерений, период,
последнее значение+статус, тренд (см. Шаг 2) — в таблицу. После таблицы
предложи пользователю выбрать показатель для детального разбора (инструмент
`AskUserQuestion`, варианты — показатели вне нормы в приоритете). После
выбора — выполни обычный сценарий (Шаги 2-5) для него.

### Несколько показателей через запятую (`Глюкоза,Гемоглобин`)
Выполни Шаги 2-5 для каждого показателя по отдельности (отдельный файл в
`Показатели/`), затем выведи одну сравнительную таблицу «дата × показатель».

### `--abnormal`
Как режим без аргументов, но таблица и создаваемые/обновляемые отчёты — только
для показателей, чьё последнее значение вне нормы.
