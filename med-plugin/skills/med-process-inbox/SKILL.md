# med-process-inbox

Обработка документов из `inbox/` в структурированный vault.

> **Оригиналы НЕ удаляются.** После обработки файл перемещается в `_processed/`.
> Это исходные медицинские документы — они могут понадобиться врачу, страховой
> или для юридических целей, а LLM-извлечение может исказить цифры.

## Использование
```
/med-process-inbox
```

## Главное правило
**Обрабатывай строго ПО ОДНОМУ файлу.** Обработал → отчёт → спроси
«продолжить?» → только после подтверждения следующий.

## Инструкции

### Шаг 1. Найди файлы
Просканируй `inbox/` (включая подпапки): PDF, JPG, JPEG, PNG. Выведи
нумерованный список. Начни с первого.

### Шаг 2. Обработка текущего файла

a) **Прочитай** инструментом Read (поддерживает PDF и изображения).
   - Если файл не читается / повреждён → **НЕ удаляй и НЕ перемещай**.
     Оставь в inbox, добавь в отчёт «пропущен (ошибка чтения)», спроси
     пользователя, что с ним делать. Никогда не уничтожай нечитаемый файл —
     возможно, это ценный документ, который просто плохо распарсился.
   - Если содержимое не похоже на медицинский документ → оставь в inbox,
     пометь «пропущен (не распознан)», спроси пользователя.

b) **Тип:** анализ / консультация / исследование / выписка.

c) **Направление:** Терапия, Кардиология, Эндокринология, Гастроэнтерология,
   Неврология, Офтальмология, Стоматология, Дерматология, Ревматология,
   Хирургия, Пульмонология. Если не определено — «Терапия».

d) **Дата:** ищи ДД.ММ.ГГГГ или ГГГГ-ММ-ДД; если нет — текущая, пометь как
   предположительную.

e) **Для анализов — показатели:** name, value, unit, norm, status.
   Статус (normal/high/low) определяй сравнением с нормой из документа.
   Если норма в документе отсутствует — сверь её через MCP-инструмент базы
   знаний `medrag` (запрос на английском: `"reference range <показатель>"`),
   и пометь, что норма взята из базы, а не из бланка.

f) **Дубликат:** сравни с файлами в `Документы/{Тип}/` по дате + ключевым
   данным. Если дубликат — **перемести оригинал в `_processed/`** (не удаляй),
   пометь «пропущен (дубликат)», перейди дальше.

### Шаг 3. Создай MD (если не дубликат)
Путь: `Документы/{Тип}/{Год}/{Дата}_{Описание}.md`. Заполни YAML frontmatter
(см. формат ниже).

### Шаг 4. Обнови связанные данные
- **Направление** `Направления/{Направление}.md`: добавь ссылку в раздел года/типа.
- **История** `Истории/{Направление}.md`: если файл существует — регенерируй
  (логика в /med-history). Если нет — пропусти.
- **Показатели** (для анализов): для каждого показателя, если
  `Показатели/{Показатель}.md` существует — регенерируй (логика в /med-metrics,
  расчёты через код). Если нет — пропусти.

### Шаг 5. Перемести оригинал
После успешного создания документа перемести файл из `inbox/` в
`_processed/{Год}/` командой `mv`. **Никогда не используй rm.**

### Шаг 6. Отчёт по файлу
Выведи: что создано, направление, дата, какие индексы обновлены, таблицу
показателей, сколько файлов осталось. Укажи, что оригинал в `_processed/`.

### Шаг 7. Спроси
«Продолжить со следующим файлом? (осталось N)» — жди подтверждения.

## Формат YAML frontmatter (анализ)
```yaml
---
date: 2025-01-15
type: анализ
category: Биохимия крови
direction: Терапия
clinic: Название клиники
metrics:
  - name: Глюкоза
    value: 5.2
    unit: ммоль/л
    norm: "3.9-6.1"
    status: normal
---
```

## Итоговая сводка
После всех файлов: обработано / создано / пропущено дубликатов / оставлено в
inbox с причиной / обновлённые направления, истории, показатели.
