# MedVault — плагин для личной медицинской документации в Obsidian

Форк [kotkaktot/MedSkill](https://github.com/kotkaktot/MedSkill) для того же
личного, медицински грамотного пользователя, что и оригинал — не для
раздачи незнакомым людям через маркетплейс. Доработки: исправлен формат
скилов (авто-активация), устранена безусловная потеря исходников при
обработке inbox, добавлен локальный RAG-слой (MedRAG) для проверки
референсов и диагностических критериев по источнику вместо памяти модели.

> **Не диагностический инструмент, но и не «только вопросы к врачу».**
> Плагин строит гипотезы о возможных системных связях и присваивает им
> достоверность — как и оригинал. Разница с оригиналом: критерии, на
> которые опирается гипотеза (пороги синдрома, диапазоны нормы), сверяются
> по базе знаний, а не берутся по памяти модели. RAG фактчекает
> **определения и критерии**, а не то, есть ли синдром у конкретного
> человека — это решение остаётся за врачом. Достоверность в отчётах
> означает «насколько данные попадают под критерии источника», не
> «вероятность диагноза у этого пациента».

## Что изменено против оригинала

- `skill.md` → `SKILL.md` + YAML frontmatter (автоактивация работает) — во всех 6 скиллах
- `med-process-inbox`: оригиналы **перемещаются** в `_processed/`, не удаляются;
  убрано авто-удаление «не распознан/повреждён» — это не смягчение под
  незнакомого пользователя (тон и гипотезы оригинала сохранены везде), а
  разовая правка, полезная независимо от того, кто и как пользуется плагином
- RAG-слой (`medrag`, коллекция `medrag_textbooks`) добавлен не только в
  `med-metrics` — он используется в 5 из 6 скиллов везде, где раньше цифра
  бралась по памяти модели:
  - `med-metrics` / `med-index` / `med-history` — сверка референсных диапазонов
  - `med-process-inbox` — сверка нормы, если она не напечатана в бланке
  - `med-merge-history` — сверка диагностических критериев синдрома
- `med-metrics`: расчёты (min/max/среднее/медиана/тренд) — только через
  исполнение кода, с явной детерминированной формулой тренда (±10% от
  среднего двух предыдущих измерений), одинаковой во всех скиллах, которые
  считают тренд
- `med-merge-history`: тон и структура (гипотезы, достоверность, корреляции)
  — как в оригинале; добавлен обязательный шаг сверки диагностических
  критериев через `medrag` перед присвоением достоверности, и переопределён
  смысл самой метки (критериям-соответствие, а не вероятность у пациента)

## Установка

### 1. Клонируй репозиторий и собери базу знаний (один раз)
```bash
git clone https://github.com/<owner>/<repo>.git <repo>
cd <repo>/med-plugin/rag
pip install -r requirements.txt
python build_index.py     # скачает MedRAG/textbooks и построит локальный индекс
```
Всё локально: default-эмбеддинги (ONNX MiniLM через `chromadb`, без
`sentence-transformers` и без API-ключей). Индекс окажется в
`<repo>/med-plugin/rag/index`.

Для запуска самого индекс-сервера нужен установленный
[`uv`](https://docs.astral.sh/uv/) — `.mcp.json` стартует его как `uvx
chroma-mcp`, отдельно ставить `chroma-mcp` не нужно, `uvx` подтянет его сам.

### 2. Плагин — ставь ИЗ ТОГО ЖЕ КЛОНА, где собран индекс
`.mcp.json` в корне плагина читает индекс из `${CLAUDE_PLUGIN_ROOT}/rag/index`.
При установке через `/plugin marketplace add <owner>/<repo>` (по GitHub)
Claude Code копирует плагин в свой кэш, и `CLAUDE_PLUGIN_ROOT` будет
указывать на пустую копию без индекса — `medrag` молча не найдёт ничего.
Поэтому ставь плагин **путём к локальному клону**, где ты только что
собрал индекс (каталог маркетплейса — `.claude-plugin/marketplace.json` в
корне репозитория; marketplace `medskill-fork`, плагин `medvault` →
`./med-plugin`):
```
/plugin marketplace add <путь_к_локальному_клону>
/plugin install medvault@medskill-fork
```
`.mcp.json` в корне плагина — стандартное место, Claude Code подхватывает его
автоматически без ссылки из `plugin.json`; при активации плагина сам поднимает
локальный `chroma-mcp`.

### 3. Vault
```
/med-init      # в пустой директории — создаёт структуру vault
```

## Приватность
База знаний и индекс не покидают твою машину. Но содержимое твоих документов
уходит в Claude API в момент чтения агентом — это свойство Claude Code,
RAG на него не влияет.

## Стек (всё бесплатно, Apache 2.0 / открытые лицензии)
ChromaDB · chroma-core/chroma-mcp (через `uv`/`uvx`) · ONNX MiniLM (default embeddings, локально) · MedRAG Textbooks
